03向量维度与去重

Qwen3-VL-Embedding-2B 支持 Matryoshka Representation Learning (MRL)，输出维度可从 64 到 2048 灵活配置。推荐方案：

  • 入库向量：2048 维（最高精度，确保召回质量）
  • 检索向量：512 维（通过 MRL 截断，速度提升 4 倍，召回率仅降 ~3%）
  • 快速初筛：128 维（Top-K 粗筛，再用 2048 维精排）

去重策略

入库前计算文件 MD5 哈希，查询 Qdrant payload 中的 file_hash 字段。已存在的文件跳过重新索引，仅更新元数据。

04b基于内容推荐 (Item-to-Item)

上节描述的是查询驱动的搜索流程（用户输入文字/图片/音频 → 向量检索）。本节描述内容驱动的推荐流程：用户已索引一个视频，第二次请求时基于该视频找相似内容。两种模式对比如下：

维度查询驱动搜索内容驱动推荐 (Item-to-Item)
触发方式用户输入文字/图片/音频客户端传已索引条目的 item_id
查询向量来源实时计算（Embedding/VLM/CLAP）从 Qdrant 取回已存储的向量
计算开销需要跑模型生成向量零重复计算，直接取回
延时3-8s（含向量化）2-5s（省去向量化步骤）
适用场景主动搜索"看了这个还看了"、相似内容推荐

核心设计原则：向量不离开服务端

客户端不需要也不应该接触原始向量。推荐流程如下：

  • 索引阶段：文件经 VLM/ASR/CLAP 处理后，向量存入 Qdrant，客户端获得 item_id
  • 推荐阶段：客户端仅发送 item_id，服务端从 Qdrant 取回向量 → 检索 → 精排 → 返回结果
  • 标签的角色：作为可选过滤条件（如"只推荐同类型视频"），不参与向量计算
  • MD5 的角色：用于缓存键和去重，不用于推荐检索

ItemRecommender 实现

class ItemRecommender:
    """基于已索引内容的推荐引擎 — 向量复用，零重复计算"""

    async def recommend_by_item(
        self,
        item_id: str,
        top_n: int = 10,
        filters: dict = None,
        mmr_lambda: float = 0.5,
    ) -> dict:
        # ① 从 Qdrant 取回该条目的存储向量（无需重新处理文件）
        source = await qdrant.retrieve(
            collection="media_items",
            ids=[item_id],
            with_vectors=True,    # 取回向量
            with_payload=True,    # 取回标签/描述
        )

        if not source:
            raise NotFoundError(f"item_id {item_id} 不存在")

        source_vectors = source[0].vector
        source_payload = source[0].payload

        # ② 用取回的向量搜索相似内容（排除自身）
        search_results = []

        # 主向量检索（画面/文本）
        if "content_vector" in source_vectors:
            visual_hits = await qdrant.search(
                collection="media_items",
                query_vector=source_vectors["content_vector"],
                query_filter=build_filter(filters, exclude_id=item_id),
                limit=100,
                with_payload=True,
            )
            search_results.append(visual_hits)

        # 音频向量检索（如果源条目有音频向量）
        if "audio_vector" in source_vectors:
            audio_hits = await qdrant.search(
                collection="media_items",
                query_vector=source_vectors["audio_vector"],
                query_filter=build_filter(filters, exclude_id=item_id),
                limit=100,
                with_payload=True,
            )
            search_results.append(audio_hits)

        # ③ RRF 融合多路检索结果
        if len(search_results) > 1:
            candidates = reciprocal_rank_fusion(
                search_results,
                weights=[0.7, 0.3],  # 画面 0.7, 声音 0.3
            )
        else:
            candidates = search_results[0]

        # ④ Reranker 精排
        source_desc = source_payload.get("description", "")
        reranked = await reranker.rerank(
            query_text=source_desc,
            candidates=candidates[:20],
            top_k=top_n,
        )

        # ⑤ MMR 多样性重排
        mmr_ids = maximal_marginal_relevance(
            query_vector=source_vectors["content_vector"],
            candidate_vectors=[c["vector"] for c in reranked],
            candidate_ids=[c["item_id"] for c in reranked],
            lambda_param=mmr_lambda,
            k=top_n,
        )

        # ⑥ LLM 生成推荐理由
        final = [c for c in reranked if c["item_id"] in mmr_ids]
        explained = await llm_explainer.explain(
            source=source_payload,
            candidates=final,
        )

        return {
            "source_item": {
                "item_id": item_id,
                "description": source_desc,
                "tags": extract_tags(source_payload),
            },
            "recommendations": explained,
        }


def build_filter(
    filters: dict = None, exclude_id: str = None
) -> dict:
    """构建 Qdrant 过滤条件：标签过滤 + 排除自身"""
    conditions = []

    # 排除源条目自身
    if exclude_id:
        conditions.append({
            "key": "id",
            "match": {"except": exclude_id},
        })

    # 标签过滤（可选）
    if filters:
        for tag_field, values in filters.items():
            if values:
                conditions.append({
                    "key": tag_field,
                    "match": {"any": values},
                })

    return {"must": conditions} if conditions else None

Item-to-Item 推荐的关键优势

  • 零重复计算：向量在索引时已存入 Qdrant，推荐时直接取回使用，不重新跑 VLM/ASR/CLAP
  • API 简洁：客户端只需传 item_id，不需要理解向量、维度等内部细节
  • 支持双向量：如果源是视频（画面+声音），两路向量都参与检索并 RRF 融合
  • 标签是加分项：可作为过滤条件缩小候选池（如"只推荐同类型视频"），但不参与向量计算
  • 延时更低：省去向量化步骤，比查询驱动搜索快 1-3s

05精排策略

06向量融合策略

视频"画面+声音"模式会产生两组向量（content_vector + audio_vector），需要策略来融合检索结果。

方案对比

方案原理优点缺点适用场景
双向量独立检索分别在两个向量空间检索，结果取并集精度高，各模态独立排序需要合并逻辑跨模态搜索
加权平均融合score = α × 画面相似度 + (1-α) × 音频相似度简单，一个分数需要调参 α综合推荐
RRF (Reciprocal Rank Fusion)score = Σ 1/(k + rank_i)，k=60无需归一化，抗尺度差异忽略分数绝对值多路召回融合（推荐）
投影到统一空间训练线性映射将 CLAP 向量投影到文本嵌入空间真正统一空间需要训练数据长期方案

系统默认方案：RRF + 加权融合

def reciprocal_rank_fusion(
    results: list[list[dict]],
    weights: list[float] = None,
    k: int = 60,
) -> list[dict]:
    """
    RRF 融合多路检索结果
    results: 各路的检索结果列表，每个结果包含 item_id 和 score
    weights: 各路权重（可选），默认等权
    k: RRF 常数（标准值 60）
    """
    if weights is None:
        weights = [1.0] * len(results)

    scores = {}
    for result_list, weight in zip(results, weights):
        for rank, item in enumerate(result_list):
            item_id = item["item_id"]
            rrf_score = weight / (k + rank + 1)
            scores[item_id] = scores.get(item_id, 0) + rrf_score

    # 按融合分数排序
    ranked = sorted(scores.items(), key=lambda x: -x[1])
    return [{"item_id": id, "score": s} for id, s in ranked]


# 视频画面+声音检索示例
visual_results = qdrant.search(content_vector, limit=100)   # 画面路
audio_results = qdrant.search(audio_vector, limit=100)      # 声音路

# RRF 融合（画面权重 0.7，声音权重 0.3 — 可配置）
fused = reciprocal_rank_fusion(
    [visual_results, audio_results],
    weights=[0.7, 0.3],
)

融合策略选择规则

  • 查询和被查都是同模态：单路检索，无需融合
  • 视频条目有双向量：查画面向量 → 画面路；查音频向量 → 声音路；查文本 → 两路都查 + RRF 融合
  • 跨模态搜索（以音搜视频）：声音路为主（权重 0.8），画面路为辅（权重 0.2）
  • 通用推荐：两路等权 RRF 融合
  • 权重可配置：通过 config.yaml 的 fusion_weights 调整

def file_md5(file_path: str) -> str:
    """计算文件 MD5（用于缓存键）"""
    h = hashlib.md5()
    with open(file_path, "rb") as f:
        for chunk in iter(lambda: f.read(8192), b""):
            h.update(chunk)
    return h.hexdigest()

async def analyze_with_cache(file_path: str, analyzer_func, cache, *args):
    """带缓存的通用分析函数"""
    md5 = file_md5(file_path)
    cache_key = f"{md5}:{file_path}"

    # 1. 检查 L2 磁盘缓存
    cached = cache.get(cache_key)
    if cached is not None:
        return cached

    # 2. 执行分析
    result = await analyzer_func(file_path, *args)

    # 3. 写入缓存
    cache.set(cache_key, result)

    return result

缓存失效场景

  • 文件修改：MD5 变化 → 自动 miss → 重新计算
  • 模型升级：缓存 key 加入模型版本号 {md5}:{model_version} → 新模型自动重算
  • 手动清除：API DELETE /api/v1/cache?type=descriptions 清除指定缓存
  • 磁盘空间不足：diskcache 自动 LRU 驱逐最旧条目
