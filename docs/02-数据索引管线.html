02视频索引流程

视频包含画面轨道和声音轨道两条信息流。系统采用模块化设计：画面分析和声音分析是独立模块，业务层可自由组合。视频支持两种画面处理方案：

方案对比：直接传送 vs 抽帧

维度方案 A：直接传送方案 B：ffmpeg 抽帧
原理视频文件直接传入模型 processor
模型内部自动抽帧		ffmpeg 先抽帧为图片序列
再将图片列表传入模型
帧选择控制模型自动决定（通常均匀采样）完全可控（1fps / 关键帧 / 自定义）
分辨率控制模型内部缩放可指定 720p / 1080p / 原图
音频保留部分实现保留（transformers）不保留（需单独提取音轨）
内存控制不透明，由 processor 决定精确可控（帧数 × 分辨率）
实现复杂度简单（一行代码）中等（需 ffmpeg + 帧管理）
调试能力无法查看中间帧可预览/调试每帧
MLX 兼容性mlx-vlm 有 bug（Qwen3-VL）完全兼容（已验证）

何时用直接传送？

  • 短视频（< 30s）：帧数少，模型自动采样足够
  • 快速原型/调试：不需要精细控制，先跑通流程
  • 使用 transformers 后端：Qwen3-VL processor 原生支持视频路径
  • 不需要音轨分离：只关心画面内容

何时用 ffmpeg 抽帧？

  • 中长视频（> 30s）：需要控制帧数避免内存溢出
  • MLX 后端：mlx-vlm 的视频处理有 bug，必须手动抽帧
  • 需要音轨分离：同时提取音频走 ASR/CLAP（直接传送不分离音轨）
  • 需要关键帧检测：长视频只需场景切换帧
  • 需要精确分辨率控制：如 720p 降采样节省 vision tokens
  • 生产环境：可控、可调试、可优化

系统默认策略

根据视频时长自动选择方案：

  • ≤ 30s + transformers 后端：直接传送（简单快速）
  • > 30s 或 MLX 后端：ffmpeg 抽帧（可控安全）
  • 需要声音分析：必须抽帧方案（同时提取音轨）
  • 用户可强制指定：video_method: "direct" | "frames" | "auto"

模块化设计的核心优势

  • 独立调用：每个模块可单独使用，如只跑声音分析模块做 ASR 服务
  • 业务自由组合：视频推荐 = 画面 + 声音；以图搜视频 = 图片模块 → 检索视频向量
  • 独立优化：每个模块可单独缓存、批量处理、横向扩展
  • 独立部署：高频模块（如 VLM/Embedding）常驻，中频模块（如 LLM/Reranker）热缓存，低频模块（如 TTS）冷加载
  • 统一接口：所有模块输出 {vector, description, tags} 标准格式，业务层无需关心内部实现

模块标准接口

# 所有分析模块统一输出格式
class AnalysisResult:
    vectors: dict[str, list[float]]   # {"content_vector": [...], "audio_vector": [...]}
    description: str                   # 富文本描述
    tags: dict[str, list[str]]         # {"category": [...], "style": [...], ...}
    metadata: dict                     # 模块特定元数据

# 各模块接口
class VisualModule:
    async def analyze(file_path: str, method: str = "auto") -> AnalysisResult

class AudioModule:
    async def analyze(file_path: str) -> AnalysisResult

class ImageModule:
    async def analyze(file_path: str) -> AnalysisResult

class TextModule:
    async def analyze(text: str) -> AnalysisResult

# 业务组合示例
async def index_video(file_path: str, mode: str = "both"):
    if mode in ("visual", "both"):
        visual_result = await visual_module.analyze(file_path, method="auto")
    if mode in ("audio", "both"):
        audio_result = await audio_module.analyze(file_path)
    # 合并结果，存入 Qdrant
    return merge_results(visual_result, audio_result)

音频类型自动判断策略

系统通过能量分析 + 语音活动检测 (VAD) 自动判断音频类型：

  • 语音占比 > 70%：走 ASR 路径（播客、对话、演讲、有声书）
  • 语音占比 < 30%：走 CLAP 路径（纯音乐、环境音、音效）
  • 混合内容：双路并行 — ASR 提取语音文本 + CLAP 提取音频特征（MV、带 BGM 的视频）

CLAP 模型只有 0.15B 参数（~0.6GB），与 ASR 互斥加载，不会同时占用内存。

07ffmpeg 精确命令

视频抽帧命令

# 短视频 (< 60s) — 1fps 抽帧，720p 降采样
ffmpeg -i input.mp4 \
  -vf "fps=1,scale=1280:720:force_original_aspect_ratio=decrease,pad=1280:720:(ow-iw)/2:(oh-ih)/2" \
  -q:v 2 \
  frames/frame_%04d.jpg

# 中视频 (60s-5min) — 每3秒1帧
ffmpeg -i input.mp4 \
  -vf "fps=1/3,scale=1280:720:force_original_aspect_ratio=decrease,pad=1280:720:(ow-iw)/2:(oh-ih)/2" \
  -q:v 2 \
  frames/frame_%04d.jpg

# 长视频 (> 5min) — 关键帧检测（场景切换帧）
ffmpeg -i input.mp4 \
  -vf "select='gt(scene,0.4)',scale=1280:720" \
  -vsync vfr \
  -q:v 2 \
  frames/frame_%04d.jpg

# 视频首帧（缩略图）
ffmpeg -i input.mp4 \
  -vframes 1 \
  -vf "scale=512:512:force_original_aspect_ratio=decrease" \
  -q:v 2 \
  thumbnail.jpg

音轨提取命令

# 从视频提取完整音轨（WAV 16kHz 单声道，ASR 标准格式）
ffmpeg -i input.mp4 \
  -vn \
  -acodec pcm_s16le \
  -ar 16000 \
  -ac 1 \
  audio.wav

# 从视频提取音轨（48kHz 立体声，CLAP 标准格式）
ffmpeg -i input.mp4 \
  -vn \
  -acodec pcm_f32le \
  -ar 48000 \
  -ac 2 \
  audio_clap.wav

# 音频切片（长音频分段处理，每段 30s）
ffmpeg -i input.wav \
  -f segment \
  -segment_time 30 \
  -c copy \
  segment_%03d.wav

# 音频静音检测（用于判断是否需要 ASR）
ffmpeg -i input.wav \

08VAD 语音活动检测

使用 Silero VAD（轻量级，~2MB，CPU 运行 < 1ms/帧）进行语音检测，结合能量分析判断音频类型。

import torch
from silero_vad import load_silero_vad, read_audio, get_speech_timestamps

class AudioTypeDetector:
    """音频类型检测器 — Silero VAD + 能量分析"""

    def __init__(self):
        self.vad_model = load_silero_vad()

    def detect(self, audio_path: str) -> dict:
        """检测音频类型，返回 {type, speech_ratio, segments}"""
        # 1. Silero VAD 检测语音段
        wav = read_audio(audio_path, sampling_rate=16000)
        timestamps = get_speech_timestamps(
            wav, self.vad_model,
            threshold=0.5,         # 语音概率阈值
            min_speech_duration_ms=250,
            min_silence_duration_ms=500,
        )

        # 2. 计算语音占比
        total_speech = sum(t["end"] - t["start"] for t in timestamps)
        total_duration = len(wav)
        speech_ratio = total_speech / total_duration

        # 3. 能量分析 — 检测是否有持续环境音
        energy = torch.abs(wav).float()
        avg_energy = energy.mean().item()
        energy_variance = energy.var().item()

        # 4. 分类
        if speech_ratio > 0.7:
            audio_type = "speech"       # 播客、对话、演讲
        elif speech_ratio < 0.3:
            audio_type = "ambient"      # 纯音乐、环境音
        else:
            audio_type = "mixed"        # MV、带 BGM 的视频

        return {
            "type": audio_type,
            "speech_ratio": speech_ratio,
            "segments": timestamps,      # 语音时间段
            "avg_energy": avg_energy,
            "energy_variance": energy_variance,
            "duration_s": total_duration / 16000,
        }

音频路由决策表

speech_ratioavg_energy判定类型路由
> 0.7—speech仅 ASR
< 0.3—ambient/music仅 CLAP
0.3 - 0.7—mixedASR + CLAP 并行
任意< 阈值silent跳过音频处理
