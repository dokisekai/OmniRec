03内存分配预算

24GB 统一内存的精细分配方案，确保常驻模型 + 系统开销在安全范围内：

内存管理策略（三级加载）

常驻集（~7.4GB）：VLM (5.4G) + Embedding (2.0G) — 这两个模型在推荐流程中被高频调用，始终保持在内存中。

热缓存（~4.6GB）：LLM (1.3G) + Reranker (2.0G) + ASR (0.7G) + CLAP (0.6G) — 仅在处理搜索、精排或音频输入时加载，5分钟无调用自动卸载。注意 ASR 和 CLAP 互斥加载（语音走 ASR，音乐/环境音走 CLAP），实际峰值仅 +4.0GB 而非 +4.6GB。

冷加载（~2.4GB）：TTS (2.4G) — 仅语音合成时加载，用完即卸。

系统 + 向量库（~3.5GB）：macOS + Qdrant + Python 运行时 + KV Cache。

安全余量（~6.1GB）：防止峰值溢出。

注意：LM Studio 的限制

LM Studio 同时只能加载 1 个模型，且没有 Embeddings API 端点。因此所有模型通过 Python + MLX/transformers 直接加载，绕过 LM Studio。VLM 已验证可用 MLX 4-bit 运行，其他模型使用 transformers + MPS 后端。

04内存管理器实现

内存管理器是系统稳定运行的核心。24GB 物理内存需要精确分配，避免 OOM 导致系统卡顿。

三层模型管理策略

层级模型加载策略卸载条件内存占用
L0 常驻VLM + Embedding系统启动时加载，永不卸载仅系统关闭时释放7.4 GB
L1 热缓存LLM / ASR / CLAP / Reranker首次调用时加载，保留 5 分钟5 分钟无调用 → 卸载1.3 / 0.7 / 0.6 / 2.0 GB
L2 冷加载TTS每次调用时加载调用完成立即卸载2.4 GB

并发控制与 LRU 驱逐

class MemoryManager:
    """模型内存管理器 — LRU + 信号量并发控制"""

    # 常驻模型（永不卸载）
    RESIDENT = {"vlm", "embedding"}

    # 热缓存模型（5分钟TTL）
    WARM_CACHE = {"llm", "asr", "clap", "reranker"}
    WARM_TTL = 300  # 秒

    # 冷加载模型（用完即卸）
    COLD_LOAD = {"tts"}

    # 内存安全阈值
    MEMORY_LIMIT_GB = 20.0  # 预留 4GB 给系统
    MODEL_MEMORY = {
        "vlm": 5.4, "embedding": 2.0, "llm": 1.3,
        "asr": 0.7, "clap": 0.6, "reranker": 2.0, "tts": 2.4,
    }

    async def acquire(self, model_name: str) -> ModelHandle:
        """获取模型句柄，必要时驱逐 LRU 模型"""
        # 1. 常驻模型直接返回
        if model_name in self.RESIDENT:
            return self._get_handle(model_name)

        # 2. 检查是否已在内存
        if model_name in self._loaded:
            self._touch(model_name)  # 更新 LRU 时间
            return self._get_handle(model_name)

        # 3. 需要加载 — 先检查内存预算
        needed = self.MODEL_MEMORY[model_name]
        while self._current_usage() + needed > self.MEMORY_LIMIT_GB:
            victim = self._evict_lru()  # 驱逐最久未使用的非常驻模型
            if victim is None:
                raise MemoryError(f"无法加载 {model_name}，内存不足")

        # 4. 加载模型
        await self._load_model(model_name)
        self._touch(model_name)
        return self._get_handle(model_name)

    def _evict_lru(self) -> str | None:
        """LRU 驱逐：优先驱逐冷加载模型，再驱逐热缓存中最久的"""
        # 跳过常驻模型和正在使用的模型
        candidates = [m for m in self._loaded
                      if m not in self.RESIDENT
                      and m not in self._in_use]
        if not candidates:
            return None
        # 按 last_access 时间排序，驱逐最久的
        return min(candidates, key=lambda m: self._last_access[m])

    async def release(self, model_name: str):
        """释放模型引用（冷加载模型立即卸载）"""
        if model_name in self.COLD_LOAD:
            await self._unload_model(model_name)
        # 热缓存模型保留，等待 TTL 过期或被 LRU 驱逐

05并发控制

并发请求处理

  • 信号量限制：每个模型一个 asyncio.Semaphore，VLM 并发上限 2（内存限制），Embedding 并发上限 8
  • 请求队列：超出并发上限的请求进入 FIFO 队列，超时 60s 自动拒绝
  • 模型切换锁：加载/卸载模型时持有写锁，推理时持有读锁，避免切换冲突
  • ASR 与 CLAP 互斥：两者不同时需要（语音 vs 音乐），共享一个槽位，不会同时占用
